# Data Assistant

AI-чат, который анализирует данные и картинки, строит графики и умеет собирать из них отчёты.

Загружаете таблицу (CSV, Excel или JSON) или изображение, пишете вопрос обычным языком — например «сделай короткий анализ» или «построй график продаж по месяцам» — и ассистент сам решает, что нужно сделать: посчитать статистику, построить график или собрать документ с выводами.

Работает на FastAPI (Python), а на странице используется HTMX — это значит, что при отправке сообщения не перезагружается вся страница, обновляется только сама переписка.

---

## Что умеет приложение

- Ведёт обычный чат, как мессенджер, с историей сообщений.
- Принимает файлы: CSV, Excel (.xlsx/.xls), JSON и изображения (PNG, JPG, BMP, GIF, WEBP).
- Отправляет данные в OpenAI и получает содержательный ответ, а если ключ API не настроен — считает базовую статистику сам, без нейросети.
- Строит графики: линейный, столбчатый, гистограмму, круговую диаграмму и точечный график.
- Сохраняет результаты анализа в отчёт формата DOCX и в короткую сводку в формате Markdown.
- Даёт скачать любой построенный график или отчёт прямо из чата.
- Хранит историю всех чатов в базе данных, так что при перезапуске сервера ничего не теряется.

## Из чего состоит проект

Если открыть папку проекта, там будет несколько основных разделов.

```
app/
  core/          настройки, логирование, безопасность — служебная часть
  services/      вся логика: работа с файлами, чат, графики, отчёты
  routes/        адреса сайта (что происходит, когда вы нажимаете кнопку)
  providers/     подключение к OpenAI
  prompts/       готовые роли для ассистента (аналитик, маркетолог и т.д.)
  db/            подключение к базе данных
  repositories/  сохранение и чтение истории чатов
templates/       HTML-страницы, которые видит пользователь
static/          стили (CSS) и код для браузера (JavaScript)
tests/           автоматические тесты, проверяющие, что всё работает
examples/        примеры файлов для тестирования (готовые CSV-таблицы)
```

Разберём подробнее, за что отвечает каждая папка.

### app/core — настройки и служебные вещи

Здесь нет бизнес-логики, только то, что нужно всему приложению сразу.

- **config.py** — читает файл `.env` и собирает из него все настройки в одном месте.
- **logging.py** — настраивает, как выглядят логи в консоли (какого уровня и в каком формате).
- **deps.py** — создаёт нужные сервисы один раз и передаёт их туда, где они нужны.
- **security.py** — отвечает за безопасные ссылки на скачивание файлов и за проверку ключа доступа.
- **middleware.py** — добавляет к каждому запросу уникальный номер и замеряет время ответа, это видно в логах.
- **rate_limit.py** — не даёт закидать сервер запросами: ограничивает их число в минуту с одного адреса.
- **cache.py** — запоминает уже посчитанный анализ, чтобы не считать его заново каждый раз.

### app/services — вся логика приложения

Самая важная папка: здесь происходит настоящая работа с данными.

- **file_service.py** — принимает загруженный файл, проверяет его формат и размер, читает содержимое таблиц.
- **chat_service.py** — управляет диалогом: сохраняет сообщения, передаёт вопрос ассистенту, запускает нужные действия.
- **ai_service.py** — общается с языковой моделью и подставляет нужную «роль» ассистента.
- **analysis_service.py** — считает статистику по таблице: средние значения, тренды, необычные выбросы.
- **chart_service.py** — рисует графики через библиотеку matplotlib и сохраняет их как картинки.
- **report_service.py** — собирает результаты анализа в отчёт формата DOCX.
- **export_service.py** — сохраняет короткую текстовую сводку.
- **storage_cleanup.py** — удаляет старые загруженные файлы, чтобы диск не переполнялся.

### app/routes — адреса сайта

Каждый файл здесь отвечает за конкретное действие, которое можно выполнить в браузере.

- **pages.py** — открывает страницы: главную, страницу чата, предпросмотр файла.
- **chat.py** — принимает отправленное в чат сообщение.
- **upload.py** — принимает загрузку файла.
- **actions.py** — запускает анализ, построение графика или отчёта, отдаёт файлы на скачивание.
- **health.py** — показывает, жив ли сервер (используется Docker'ом, чтобы проверять состояние приложения).
- **api.py** — отдельный адрес, который возвращает результат анализа в чистом виде (JSON), без интерфейса.

### templates — то, что видит пользователь

HTML-страницы, собранные с помощью Jinja2. Часть из них — это полноценные страницы (например, `chat.html`), а часть — небольшие кусочки (`partials/`), которые подгружаются и заменяются на странице без перезагрузки, когда вы отправляете сообщение или загружаете файл.

### storage — здесь хранятся файлы

Эта папка появляется автоматически при первом запуске и не хранится в GitHub, потому что в ней лежат ваши личные данные.

- `uploads/` — файлы, которые вы загрузили.
- `outputs/` — графики и отчёты, которые создал ассистент.
- `cache/` — временные результаты анализа.
- база данных с историей всех чатов.

## Как запустить проект у себя

Понадобится Python версии 3.11 или новее.

### 1. Скачайте проект

```bash
git clone https://github.com/Gagggar1/data_assist.git
cd data_assist
```

### 2. Создайте виртуальное окружение и поставьте зависимости

Виртуальное окружение — это отдельная «песочница» для библиотек проекта, чтобы они не смешивались с другими программами на компьютере.

Windows:

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

macOS / Linux:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 3. Настройте файл с секретными данными

В проекте есть файл-образец `.env.example`. Скопируйте его и переименуйте в `.env`:

```bash
copy .env.example .env      # Windows
cp .env.example .env        # macOS / Linux
```

Откройте `.env` любым текстовым редактором и заполните как минимум две строки:

- `OPENAI_API_KEY` — ваш ключ доступа к OpenAI. Без него приложение всё равно запустится, но вместо ответов нейросети будет использовать простой локальный анализ.
- `APP_SECRET_KEY` — любая длинная случайная строка, она нужна для защиты ссылок на скачивание файлов.

Файл `.env` никогда не должен попадать в GitHub — он уже добавлен в `.gitignore`, так что случайно закоммитить его не получится.

### 4. Запустите сервер

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Откройте в браузере `http://127.0.0.1:8000` — должна открыться страница чата.

## Запуск через Docker

Если у вас установлен Docker, можно обойтись без ручной настройки Python.

```bash
cp .env.example .env
# заполните .env, как описано выше
docker-compose up --build -d
```

Проверить, что контейнер запустился:

```bash
docker ps
curl http://localhost:8000/health
```

Остановить:

```bash
docker-compose down
```

## Переменные окружения

Полный список — в файле `.env.example`. Самые важные:

| Переменная | Что делает |
|---|---|
| `APP_HOST` | Адрес, на котором слушает сервер. `127.0.0.1` — только с этого компьютера, `0.0.0.0` — с любого адреса, это нужно при запуске на сервере или в Docker. |
| `APP_PORT` | Порт, на котором работает сайт (по умолчанию 8000). |
| `APP_SECRET_KEY` | Секретный ключ для подписи ссылок на скачивание файлов. |
| `MAX_FILE_SIZE` | Максимальный размер загружаемого файла, например `10MB`. |
| `OPENAI_API_KEY` | Ключ доступа к OpenAI. Без него включается локальный запасной сценарий. |
| `OPENAI_MODEL` | Какую модель использовать (например, `gpt-4o` или `gpt-4o-mini`). |
| `PROMPT_ROLE` | Роль ассистента: `financial_analyst`, `marketer` или `market_trading_analyst`. |
| `RATE_LIMIT_PER_MINUTE` | Сколько запросов в минуту разрешено с одного адреса. |

---

## Роль market_trading_analyst

Отдельная роль ассистента для разбора крипты, акций и forex. Понимает скриншоты графиков (свечи, уровни) и таблицы с котировками, отвечает по структуре: что видно на графике, какие есть сценарии развития (оптимистичный / базовый / пессимистичный) и какой можно рассмотреть вход в сделку с учётом риска.

Чтобы включить:

```env
PROMPT_ROLE=market_trading_analyst
OPENAI_MODEL=gpt-4o
```

1. Откройте сайт и нажмите на область загрузки файла.
